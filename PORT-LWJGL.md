# Перевод редактора на LWJGL — сделано

Состояние на 21 сентября 2026: **перенос закончен**. Swing из проекта ушёл
целиком, пакет `ru.dw.qeditor.ui` удалён. Подробный разбор — в
[PROGRESS.md](PROGRESS.md), раздел «Перевод на LWJGL»; памятка по работе с
кодом — в [CLAUDE.md](CLAUDE.md).

Решения, принятые в начале работы (подтверждены заказчиком):

* всё приложение на GLFW + OpenGL, свой интерфейс в GL, Swing уходит совсем;
* сборка на **Maven** (обёртка `mvnw` в репозитории, ставить ничего не нужно).

## Сборка

* `DwQuestsEditor/pom.xml` — Java 17, `sourceDirectory=src` (дерево исходников
  не переносили, чтобы не ломать ссылки в документации и .bat),
  `outputDirectory=out`.
* Зависимости: LWJGL **3.3.6** — `lwjgl`, `lwjgl-glfw`, `lwjgl-opengl`,
  `lwjgl-stb`, `lwjgl-tinyfd` плюс нативные библиотеки; классификатор
  выбирается профилем по ОС.
* `maven-dependency-plugin` кладёт jar-ы в `DwQuestsEditor/lib/` — оттуда их
  берут ручной `javac`, `build.bat` и `run.bat`.
* `maven-shade-plugin` собирает самодостаточный `DwQuestsEditor.jar`
  (главный класс — `ru.dw.qeditor.Main`).
* Обёртка Maven: `mvnw`, `mvnw.cmd`, `.mvn/wrapper/maven-wrapper.properties`
  (тип `only-script`, Maven 3.9.9 скачивается сам).

```bash
cd "C:/Users/User/Desktop/dwquests/DwQuestsEditor" && ./mvnw -B compile
```

Быстрая пересборка во время работы:

```bash
cd "C:/Users/User/Desktop/dwquests/DwQuestsEditor" && javac -encoding UTF-8 -cp "lib/*" -d out -sourcepath src $(find src -name "*.java")
```

## Низкий уровень — пакет `ru.dw.qeditor.gl`

| Файл | Что делает |
|---|---|
| `GlProgram` | компиляция и линковка шейдеров |
| `GlTexture` | текстура из `BufferedImage`; «пиксельная/сглаженная/повторяющаяся» |
| `Batch` | накопитель четырёхугольников, один шейдер на все примитивы |
| `GlWindow` | окно GLFW, контекст 3.3 core, курсоры, полный экран, буфер обмена, перетаскивание файлов |
| `Input` | ввод за кадр: мышь, колесо, клавиши, набранный текст, двойной щелчок |
| `Atlas` | упаковка мелких картинок в одну текстуру («полками») |
| `Textures` | `BufferedImage` → текстура с кэшем по ссылке; атлас иконок предметов |
| `Offscreen` | кадровый буфер в картинку — для отладочных рендеров |
| `UiFont` | шрифт интерфейса: глифы растеризует AWT в память, дальше атлас |

Режимы шейдера в `Batch`: текстура, сплошной цвет, `circle.frag`,
`gradient.frag`, силуэт (обводка и текст), отрезок линии, скруглённый
прямоугольник. Смешивание — обычное и аддитивное (`GL_SRC_ALPHA, GL_ONE`).
Пакет рвётся только на смене текстуры, режима смешивания и области отсечения.

## Отрисовка — пакет `render`

* **`GuiPainter`** на OpenGL, публичный API сохранён (`rect`, `gradient`,
  `circle`, `node`, `questStar`, `item`, `texturedModalRect`, `text`,
  `push/pop`, `clip`…). Появились `of(batch, guiScale, w, h)`,
  `deviceX/deviceY`, `roundRect`, `segment`, `region/regionMask`,
  `texturedRect(..., tint)`. Убраны `g2()`, кэши спрайтов, `awt(int)`.
* **`LinkRenderer`** — ломаная разворачивается в полоску четырёхугольников
  с цветом в вершинах (как `GL_LINE_STRIP` в моде), мягкий край считает
  шейдер. Пакетного режима (`LinkRenderer.Batch`) больше нет.
* **`Fx`** — только формулы над цветом; растеризация шейдеров удалена.
* **`AdditiveComposite`** — удалён.
* **`McFont`** — раскладка та же, но вместо `Graphics2D` приёмник
  `McFont.Sink` (`glyph(...)`, `rect(...)`); `GuiPainter` его и реализует.
  Кэш перекрашенных страниц не нужен — цвет глифа это цвет вершины.
* **`GamePreview`** — `render(GuiPainter p, int pixelWidth, int pixelHeight)`.
  Кэши фона карты и рамки окна убраны (на видеокарте они дороже самой
  отрисовки), галочка красится цветом вершины, связи идут через новый
  `LinkRenderer`.

## Что нашлось по дороге

* **Ключи виджетов сравнивать по значению.** Они собираются строкой в кадре
  (`this + "name"`), поэтому `focus == id` не работает: в следующем кадре это
  другой объект. Из-за этого не работал фокус во всех полях ввода.
* **Размер окна берёт система.** Запрос 1920×1080 превращается в 1920×1061
  (рабочая область экрана). Проверки вида рисовали кадр запрошенного размера,
  отсечение съезжало на 19 точек — и текст в узких полях исчезал. Размер надо
  спрашивать у окна (`GlProbe.frameSelf` так и делает).
* `Textures.refresh()` вызывается и в `Ui.end()`, и в `GlProbe.frame()` — во
  втором случае кадр рисуется дважды, чтобы попавшие в атлас иконки успели
  получить уровни уменьшения. Для окна это не нужно (следующий кадр всё равно
  будет).
* Иконки предметов лежат в атласе 2048×2048 с запасом в 4 точки и одним уровнем
  уменьшения — при выводе мельче 16 точек может слегка мылить; если станет
  заметно, добавить второй уровень и увеличить запас.
* `Popup.takePick` отдаёт выбор следующим кадром; владелец должен забрать его
  в начале своего кадра. Если владелец исчез, выбор остаётся висеть — стоит
  гасить его через кадр-другой (счётчик возраста).
* `java.awt` остался в проекте, но только как **читалка картинок и
  растеризатор глифов** (`ImageIO`, `BufferedImage`, `Font`). Ни окон, ни
  `Graphics2D` в отрисовке больше нет.

## Что можно доделать

* Курсор в многострочном поле не знает про вставку §-кода кнопкой: код
  дописывается в конец описания, как это делал и Swing-редактор, когда поле
  было не в фокусе. Полноценная вставка по курсору потребует отдать
  `TextBuf` наружу.
* Перетаскивание строк задач мышью (в Swing-версии было) заменено кнопками
  «↑ / ↓».
* Второй уровень уменьшения в атласе иконок, если мыло на мелких иконках
  начнёт мешать.

## Дистрибутив (после переноса)

Jar-ы мода из проекта убраны: всё нужное вытащено из них в
`runtime/game/assets/…`. Читает ресурсы `assets/AssetPack` — папка на диске
либо `dwq-assets/` внутри собственного jar-а (со списком записей `index.txt`,
потому что каталог в classpath не перечислить). Настройки сократились с трёх
путей к jar-ам до двух папок, и обе можно оставить пустыми.

`package.bat` собирает в `dist/`:

* `jar/DwQuestsEditor.jar` — 111 МБ: классы, LWJGL с нативными частями и все
  ассеты. Нужна Java 17+;
* `DwQuestsEditor-win64.zip` — 134 МБ: папка с exe, иконкой и урезанной Java
  (`java.base`, `java.desktop`, `jdk.unsupported`). Получателю не нужно ничего.

Собирают это `util/Distribution` (fat jar и архив) и `util/AppIcon` (иконка —
тот же узел квеста, что редактор рисует на карте).

Найденное по дороге:

* `jdk.unsupported` в урезанной Java обязателен — LWJGL лезет в
  `sun.misc.Unsafe` и без него падает на первом же вызове GLFW.
* `.bat`-файлы должны быть в чистом ASCII: cmd читает их по смещению в байтах
  и после `chcp 65001` теряет место на не-ASCII, выдавая
  `< was unexpected at this time`. Это ломало все три старых скрипта.
* Вложенный `.bat` вызывать только как `call "%~dp0build.bat"`: текущий каталог
  в поиске команд может быть отключён (`NoDefaultCurrentDirectoryInExePath`).
* `Config.runtimeDir()` обязан проверять, что внутри есть `game` или `icons`:
  у приложения из jpackage рядом лежит своя папка `runtime` — встроенная Java.
