# DwQuests Editor — памятка для Claude

Редактор вкладок квестов мода **DwQuests** (Minecraft 1.7.10) на Java + LWJGL: окно,
интерфейс и карта — GLFW и OpenGL 3.3, свой тулкит, Swing не используется.
Проект: `DwQuestsEditor/`, подробности и история — в [PROGRESS.md](PROGRESS.md).

## Сборка и запуск

Зависимости (LWJGL 3.3.6) подтягивает обёртка Maven — сам Maven ставить не нужно:

```bash
cd "C:/Users/User/Desktop/dwquests/DwQuestsEditor" && ./mvnw -B compile
```

Быстрая пересборка во время работы — тем же ручным `javac`, jar-ы лежат в `lib/`:

```bash
cd "C:/Users/User/Desktop/dwquests/DwQuestsEditor"
find src -name "*.java" > sources.txt
javac -encoding UTF-8 -cp "lib/*" -d out @sources.txt
```

Всегда с `-encoding UTF-8` / `-Dfile.encoding=UTF-8`: иначе ломается кириллица в исходниках
и в выводе. Точка входа — `ru.dw.qeditor.Main`, запуск с `-cp "out;lib/*"`; есть
`build.bat` / `run.bat` / `dwq.bat`.

**Дистрибутив для человека — `package.bat`.** Кладёт в `dist/` два варианта, и в
обоих все ассеты внутри: `jar/DwQuestsEditor.jar` (один файл, нужна Java 17+) и
`DwQuestsEditor-win64.zip` (папка с exe и урезанной Java, не нужно ничего).
Собирает `util/Distribution` (fat jar + `dwq-assets/` + `index.txt`),
иконку рисует `util/AppIcon` тем же узлом квеста.

**`.bat`-файлы держать в чистом ASCII.** cmd читает их по смещению в байтах и
после `chcp 65001` теряет место на не-ASCII тексте — получается
`< was unexpected at this time`. Всё русское печатают java-утилиты.
И вызывать вложенные `.bat` только как `call "%~dp0build.bat"`: текущий каталог
в поиске команд может быть отключён.

## Как править квесты без GUI

Для этого есть консольный режим — им удобно пользоваться из терминала:

```bash
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.cli.QuestCli help
```

Команды читают и пишут тот же JSON, что и редактор, сохраняя неизвестные поля:

| Команда | Что делает |
|---|---|
| `info / list / show <файл> [questID]` | сводка, таблица квестов, JSON одного квеста |
| `validate <файл>` | проверка; код возврата 1, если есть ошибки |
| `audit <файл>` | сверка id предметов с базой: что в игре станет бедроком (и где) |
| `export <файл>` | компактный JSON для `/dwq tab paste` |
| `find-item <строка> [--mod M]` | поиск предмета по русскому имени или id |
| `new / set-tab` | создать вкладку, поменять tabID / иконку / sortIndex |
| `add / edit / remove / move` | квесты |
| `parent-add / parent-remove` | зависимости между квестами |
| `task-add / task-set / task-remove` | задачи |
| `reward-add / reward-remove` | награды |
| `patch --json '{…}'` | слияние JSON-патча (объекты рекурсивно, `null` удаляет ключ) |
| `tabs <папка>` | список вкладок в папке с числом квестов |
| `versions <файл>` | сохранённые версии вкладки |
| `backup <файл>` | сохранить копию прямо сейчас |
| `restore <файл> --version N` | вернуть вкладку к версии (текущее состояние тоже сохранится) |
| `link` / `link-tabs` | связь с запущенной игрой; вкладки в ней |
| `link-get <tabID> [--out f]` / `link-all <папка>` | забрать вкладки из клиента |
| `link-paste <файл> [--clipboard]` | отправить вкладку в игру |
| `link-icon <строка предмета>` | нарисовать иконку силами игры (с NBT) |
| `link-export icons\|assets\|tabs` | запустить выгрузку в самой игре |
| `link-icons-pull [--wait]` | перенести выгруженные иконки из `<клиент>/dwq_export/icons` в папку иконок редактора (`items.json` сливается) |

Общие ключи записи: `--out <файл>` (писать в другой файл), `--dry-run` (вывести JSON в stdout,
ничего не записывая), `--validate` (сразу проверить результат).

Пример: ветка из двух квестов.

```bash
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.cli.QuestCli new Botania.json --tab Botania
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.cli.QuestCli add Botania.json Начало \
  --name "Первые шаги" --x 0 --y 0 --icon minecraft:book --rarity COMMON \
  --desc "<BR>Собери первые ресурсы."
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.cli.QuestCli task-add Botania.json Начало \
  --type ITEM_DETECT --item minecraft:log --count 16
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.cli.QuestCli add Botania.json Дерево \
  --x 2 --y 0 --icon minecraft:log --parent Начало --reward "minecraft:diamond=3"
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.cli.QuestCli validate Botania.json
```

**Перед правками делай `backup`** — или просто правь: копия всё равно останется,
редактор сохраняет версию перед каждым рискованным действием. Вернуть состояние:
`versions`, затем `restore --version N`.

**Открытый в редакторе файл перечитывается автоматически**, если изменить его снаружи
(«Вид → Следить за файлом»). То есть можно держать окно открытым и править файл командами —
изменения сразу видно в поле и в просмотре.

## Мост с игрой (мод `DwQuestsBridge/`)

В репозитории лежит **клиентский мод 1.7.10** — выгрузчик ассетов и мост с
редактором. Воркспейс GTNH-convention, как у остальных модов пака; jar-ы для
компиляции берутся из клиента (свойство `clientDir`). Подробности — в
[DwQuestsBridge/README.md](DwQuestsBridge/README.md).

```bat
DwQuestsBridge\build.bat
DwQuestsBridge\install.bat
DwQuestsBridge\attach.bat     :: впрыск в уже запущенный клиент, без перезапуска
```

**Впрыск возможен только потому, что мод ничего не регистрирует в игре** —
ни предметов, ни рецептов, ни сетевых каналов, только клиентскую команду,
обработчик тика и свой HTTP-поток. `attach/dwq-attach.jar` подключается к JVM
клиента через Attach API, добавляет jar мода **в тот загрузчик, которым загружен
`net.minecraft.client.Minecraft`** (на системном пути классов мод не получит
преобразования имён FML и упадёт), и зовёт `DwqBridge.attach()`; регистрация
уходит в очередь главного потока через `Minecraft.func_152344_a`.

* Мод складывает всё в `<клиент>/dwq_export/`: `icons/` и `game/` — ровно те две
  папки, что редактор ждёт в своём `runtime/`, плюс `tabs/` и `bridge.json`.
* Выгрузка идёт **по кусочкам в тике клиента**: десять тысяч иконок одним куском —
  это минута зависания и вылет по таймауту.
* **Иконки вариантов с NBT.** Старый `icon_exporter` ключевал картинки по
  `mod:name:meta`, поэтому все цветы Botany (`Botany:itemFlower`, вид задаёт геном
  в NBT) слились в одну. Теперь в имени файла есть хвост `~хеш` от
  **приведённого** NBT (ключи отсортированы, суффиксы чисел убраны). Тот же хеш
  независимо считает редактор — `NbtLite.canonical` + `ItemRegistry.hash8`, —
  и совпадение проверяет `SelfTest`. Менять приведение можно только в обеих
  реализациях сразу.
* Всех сочетаний генома не выгрузить, поэтому главный путь для таких предметов —
  дорисовка на лету: редактор просит игру нарисовать тот самый стек
  (`link/IconFetcher` → `GET /icon?stack=…`) и кладёт ответ к остальным иконкам.
  Ходит за картинкой отдельный поток, и, получив её, будит окно
  (`GlWindow.postEmptyEvent`) — иначе кадр не перерисуется.
* Вкладки из памяти клиента неполны: `broadcast` не передаётся, строки наград
  пересобраны из стеков, а незнакомый `iconItem` уже стал бедроком. Точную копию
  даёт `/dwqb tabs raw` — через `/dwq tab copy` и буфер обмена, с правами на `/dwq`.
* **Заливка — только штатным путём**: JSON в буфер и `/dwq tab paste` от имени
  игрока. Проверку прав делает сервер, и обходить её мод не должен: обработчик
  `CSPEditTab` на сервере принимает вставку без проверки — единственное, что
  мешает залить вкладку кому угодно, это то, что команду шлёт клиент.
* **Несколько вкладок — строго по одной** (`POST /paste-all`, `quests/TabBatchUpload`).
  `/dwq tab paste` лишь просит сервер; клиент читает буфер, когда придёт ответный
  запрос, а имя вкладки берёт из запроса. Следующую вкладку в буфер можно класть
  только после ответа сервера в чат «<вкладка> успешно сохранено», иначе она
  сохранится под чужим именем. Нет ответа за 20 с — заливка останавливается.
* Выгрузки мода лежат у клиента (`dwq_export/icons`, `dwq_export/tabs`), редактор
  переносит их сам по окончании: иконки — в свою папку иконок (`link/IconImport`,
  `items.json` сливается), вкладки — в открытую папку (прежний файл уходит в версии).

## Что важно помнить про формат

* Координаты `displayX/displayY` — в клетках; в игре умножаются на **24**
  (в веб-редакторе kriss-ss — на 30, это расхождение).
* `parents` бывает строкой **или** объектом; порядок ключей в `tasks` важен.
* Реально отслеживаются сервером только `TASK_CONFIRM`, `ITEM_PASS`, `ITEM_DETECT`,
  `ITEM_CRAFT`, `ITEM_SMELT`, `ENTITY_KILL`, `PLAY_TIME` — остальные 20 типов задач мод
  принимает, но сам не засчитывает. `validate` про это предупреждает.
* `broadcast` рассылается всем игрокам один раз при выполнении квеста; плейсхолдеры
  `%nick%`, `%player%`, `%quest%`, `%tab%`, `&`-коды переводятся в `§`.
* Награда — строка: предмет `mod:name[:meta][=count][{NBT}]`, команда `command:…`,
  гифт `DwQuests:Gift:<мета>{…}`, скрипт `customnpcs:scripted_item{…}`.
* `iconSize`: DEFAULT 1.0, MEDIUM 1.5, LARGE 2.0, HUGE 2.5 — значения из мода,
  в веб-редакторе они другие и неверные.
* **Незнакомый id в игре — это бедрок.** `ForgeNameUtils.getForgeItem` молча отдаёт
  `BEDROCK` на всё, чего нет в реестре, поэтому серые кубы во вкладке — либо опечатка,
  либо мод не стоит, либо устарела база иконок. Что именно — показывает `audit`.
* **Предметы внутри гифта лежат иначе, чем везде.** `ItemGift.saveInventoryToNBT`
  пишет слот как `{Slot:0b, ID:"mod:name[:meta]=count", Tag:{…NBT…}}` — NBT отдельным
  тегом `Tag`, а не внутри строки `ID` (`ForgeNameUtils.getStackFromNBT` читает ID
  через `getForgeItemWithSize`, а тот скобки не разбирает и вернёт бедрок). Иконки,
  награды и задачи — наоборот, через `getForgeItemWithNbt`, там NBT в строке.
  В редакторе слот везде хранится одной строкой, а при записи разбирается на `ID` + `Tag`.
* `Layers` у гифта — массив чисел (`NBTTagIntArray`), пишется `[0,1]` без индексов;
  `Items` — список составных тегов, пишется `[0:{…},1:{…}]`. В 1.7.10 `JsonToNBT`
  различает их именно по этому.

## Интерфейс

Страницы окна: «Редактор» (поле с узлами), «Просмотр как в игре», «JSON»
(`app/JsonView` — выбранный квест или вся вкладка текстом; вкладка больше
120 000 символов показывается только на просмотр, потому что многострочное поле
переносит строки каждый кадр) и «Помощник Claude».

Свой тулкит в режиме немедленного вывода (`gui/Ui`, `gui/Widgets`, `gui/Popup`):
виджетов-объектов нет, каждый кадр экран описывается заново вызовами вида
`if (ui.button(x, y, w, h, "Сохранить"))`. Что важно помнить:

* Значение поля каждый кадр приходит из модели, а правка тут же уходит в модель
  через `EditorModel.edit(...)` — «тихого обновления из модели» нет вовсе.
* Ключ виджета обычно собирается строкой в кадре (`this + "questID"`), поэтому
  сравнивать ключи можно **только по значению**: в следующем кадре это другой
  объект. `Ui.focused(id)` так и делает.
* Горячие клавиши окна (`App.hotkeys`) зовутся в конце кадра и молчат, пока
  поле в фокусе (`ui.keyboardCaptured()`): Ctrl+A/C/V/Z/Y там разбирает само
  поле, у каждого своя отмена (`TextBuf`). Правки из набора склеиваются в
  истории модели в один шаг (`History.push(…, typing)`).
* Если значение поля меняют кодом (кнопка вставила §-код), надо сбросить
  состояние поля: `ui.forgetState(id)` — иначе поле в фокусе покажет старый
  текст.
* Верхние слои (меню, диалог) рисуются последними, но ввод забирают первыми:
  до отрисовки нижних вызывается `ui.blockInput()` / `Popup.blockIfOpen`.
* Перед сохранением (Ctrl+S) показывается `app/ChangesDialog` — отличия от файла на
  диске, которые считает `io/TabDiff` (обе стороны через модель, так что отступы и
  порядок полей не считаются). Выключается галкой или в настройках
  (`reviewBeforeSave`); внутренние вызовы сохраняют через `saveNow()` без окна.
* Диалог — верхний слой того же кадра (`app/Dialog`), а не отдельное окно.
  Системные диалоги файла и папки открывает tinyfd (`app/FileDialogs`).
* Координаты интерфейса — логические точки: масштаб экрана учитывает
  `Ui.scale()`, поэтому на 150 % интерфейс не мельчает. Карта и просмотр внутри
  своих прямоугольников меняют масштаб рисователя (`GuiPainter.push/scale`) —
  там единица уже клетка карты или пиксель GUI мода.
* **Верхнему слою координаты отдавать в координатах окна**: `Popup` рисуется с
  чистым началом координат, а раскрывают его виджеты изнутри прокручиваемых
  областей, где начало съехало. Отсюда `Ui.toScreenX/toScreenY` в
  `Widgets.dropdown` — без них список открывался в другом конце экрана.
  Длинный список (27 типов задач) не переворачивается, а прокручивается, и
  щелчок, которым его открыли, выбором не считается.
* **Пиксельное рисуется в целом масштабе.** Шрифт мода и его текстуры идут
  GL_NEAREST: дробный масштаб делает соседние пиксели глифа разной ширины
  («шакалит»). Поэтому `PreviewView` берёт целый guiScale, а начало координат
  прижимается к целому пикселю `GuiPainter.snap()`.
* **Кириллице нужен чётный масштаб.** Глиф из `unicode_page_xx.png` занимает
  16 пикселей, а рисуется восемью (`McFont.renderUnicodeChar`), так что на
  масштабе 1 он ещё и уменьшается вдвое — GL_NEAREST при этом выбрасывает
  каждый второй ряд текселей, и от букв остаются огрызки. Страницы шрифта
  поэтому идут `GlTexture.Filter.GLYPH`: увеличение пиксельное, уменьшение
  билинейное.
* **Предпросмотр описания рисуется в свой буфер.** Игровая метка шириной 380
  пикселей в узкую колонку целым масштабом не влезает, поэтому `McPreview`
  рисует её в `Offscreen` крупно и на чётном масштабе, а на экран кладёт
  уменьшенной картинкой с уровнями уменьшения — супер-сэмплинг вместо целого
  масштаба. Так панель можно тянуть как угодно. Переключение приёмника —
  `Batch.pushTarget/popTarget`: незаконченный пакет уходит на экран, отсечение
  снимается и возвращается обратно.
* Символов, которых нет в системном шрифте, в интерфейсе хватает (крестик
  закрытия, дуги связей, знак внимания). Java для физического шрифта подстановку
  не делает — её делает `UiFont.fallbackFor`. Узкой кнопке глиф ещё надо
  вместить: `Ui.textIn` иначе заменит его многоточием.

## Помощник Claude

Вкладка «Помощник Claude» (`app/AssistantView`, `ai/`) работает через локальный
Claude Code CLI (`claude -p --output-format stream-json`) — ключ API не нужен.

* **CLI запускается урезанным** (`ClaudeClient.arguments`): свой системный
  промпт `--system-prompt-file`, пять инструментов `--tools Read,Edit,Write,Glob,Grep`,
  пустой `--mcp-config` со `--strict-mcp-config`, `--disable-slash-commands`,
  `--setting-sources project`. По умолчанию CLI тащит в каждый запрос свой
  промпт, все инструменты, MCP-серверы и скиллы пользователя: на «привет»
  37 тыс. токенов против 3,6 тыс. Флаги без пробелов и кавычек — всё
  сложное лежит файлами, потому что на Windows CLI идёт через `cmd.exe /c`.
* **Вкладка лежит файлами** (`ai/TabWorkspace`, `%TEMP%/dwq-assistant/<вкладка>/`):
  `tab.json`, `quests/<id>.json` (id в поле `questID`), `map.txt` — сводка для
  Grep. Модель читает только нужное и правит `Edit`-ом, новые квесты пишет
  `Write`-ом, удаление — файл со словом `null`. Потом `read()` собирает вкладку
  обратно, а «Применить» переносит только то, что поменял помощник
  относительно вкладки на момент отправки.
* **Пути в промпте абсолютные**: Read/Edit/Write относительных не принимают, а
  Grep без `path` виснет на 20 с. Без этого модель теряла по два круга.
* Разговор продолжается (`--resume` с тем же id сеанса), пока вкладка та же;
  нетронутые файлы при пересборке не переписываются — перечитывать их модели
  не нужно.
* Страница «Что уйдёт» показывает команду, сообщение и системный промпт ровно
  тем текстом, что получит CLI; «Ход работы» — поток событий (какие файлы
  читает и правит); «Изменения» — разница и проверка. «Прервать» гасит всё
  дерево процессов, иначе за `cmd.exe` продолжал бы работать сам claude.
* Галка «со снимком карты» кладёт `tab.png` (`ai/TabShot`, тот же
  `GamePreview`, что и просмотр) в каталог вкладки. Снимок рисуется **после**
  `batch.end()`: пакет вершин на окно один.
* Живые проверки (стоят центы): `util/AssistantCheck` — правка, создание и
  удаление через файлы; `util/AssistantUiCheck` — то же через окно, с
  продолжением разговора.

## Ресурсы

`runtime/` в корне репозитория: `icons/` — иконки предметов и `json/items.json`,
`game/assets/…` — текстуры мода и шрифт Minecraft, вытащенные из jar-ов. Самих
jar-ов мода в проекте больше нет: всё нужное лежит распакованным, поэтому ни
клиент, ни моды не нужны.

Читает это `AssetPack`: папка на диске (`runtime/`) либо ресурсы внутри
собственного jar-а (`dwq-assets/`, с `index.txt` — каталог в classpath иначе
не перечислить). Порядок поиска в `Config.autodetect()`: пути из настроек →
`runtime/` рядом с программой → встроенное в jar → установленный клиент.
`Config.runtimeDir()` требует внутри `game` или `icons`: у собранного
jpackage приложения рядом своя папка `runtime` — это встроенная Java.
Распаковка `work/` в репозиторий не входит.

## Скорость

Вкладки бывают на тысячу квестов и столько же связей. Рисует видеокарта, и
главный прежний тормоз — аддитивное свечение узлов на процессоре — исчез:
1200 квестов и 1274 связи на 1920×1080 дают ~17 мс на кадр (59 к/с) в поле
редактора и ~7 мс (139 к/с) в просмотре. Что важно помнить при правках рендера:

* Всё идёт одним пакетом вершин (`gl/Batch`), один шейдер на все примитивы.
  Пакет рвётся только на смене текстуры, режима смешивания и области
  отсечения — то есть новый вызов отрисовки надо «заслужить».
* Иконки предметов и глифы лежат в атласах, поэтому четыреста разных иконок
  не стоят четырёхсот вызовов отрисовки.
* Дуга связи считается замкнутой формулой, хватает 24 вершин вместо 250.
* Узлы и связи за пределами экрана пропускаются — это по-прежнему самая
  дешёвая оптимизация.
* Кэшировать картинками (фон карты, рамку окна, спрайты нодов) больше не надо
  и не нужно: на видеокарте пересборка дешевле, чем копия из памяти.
* Градиент цвета вдоль связи выключается на мелком масштабе
  (`LinkRenderer.gradientWorthIt`) — разницы не видно, а вершин вдвое меньше.
* Кадры рисуются не всё время: пока ничего не происходит, окно ждёт события
  (`GlWindow.waitEvents`). Постоянный поток кадров нужен только просмотру,
  где идёт анимация.

Замер: `java -cp "out;lib/*" ru.dw.qeditor.util.Bench вкладка.json 20 1920 1080`,
подробности по этапам — с `-Ddwq.profile=true`.
Тестовые вкладки на 24 / 120 / 400 / 1200 квестов — в `DwQuestsEditor/testquests/`
(пересобрать другого размера: `python testquests/make.py`).

## Проверка вида

Отладочные рендеры: окно GLFW создаётся скрытым, кадр рисуется в кадровый
буфер и уходит в PNG — поверх того, что открыто на экране, ничего не всплывает.

```bash
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.util.SelfTest
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.util.PainterProbe probe.png
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.util.FontProbe font.png
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.util.PreviewProbe .
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.util.UiProbe ui.png вкладка.json 0
java -Dfile.encoding=UTF-8 -cp "out;lib/*" ru.dw.qeditor.util.UiProbe ui.png вкладка.json 1 1920 1080 full
```

С `-Ddwq.probe.changes=другая.json` `UiProbe` подменяет содержимое вкладки и снимает
окно несохранённых изменений.

`UiProbe` рисует настоящее окно редактора (`App.drawFrame`), так что им сверяется
весь интерфейс, а не только карта.

Проверки механики: `FullscreenCheck` (полный экран туда-обратно, запускать с
`-Ddwq.nofullscreen=true`, чтобы не занимать экран), `RotateCheck` (поворот группы за ручку: 90° вокруг центра, сотые, связи и отмена), `GhostCheck` (после ухода
камеры в пустоту в поле должен остаться только фон) и `DragCheck` (щелчок по
квесту выделяет и не двигает, перетаскивание двигает) и `TextKeysCheck` (в поле
ввода Ctrl+A/C/V/Z/Y работают с текстом, а не с квестами; набор — один шаг отмены). Тем же ключом
`-Ddwq.nofullscreen=true` можно отключить захват экрана в самой программе.

Жесты мыши проверкам подсовывает `gl/InputProbe` — те же события, что шлёт GLFW,
но руками; между двумя нажатиями в одной точке нужна пауза, иначе выйдет двойной
щелчок.

**Размер окна спрашивать у окна.** Система урезает его до рабочей области:
запрос 1920×1080 превращается в 1920×1061. Кадр другого размера сдвигает
отсечение, и текст в узких полях исчезает — на этом уже попадались.
